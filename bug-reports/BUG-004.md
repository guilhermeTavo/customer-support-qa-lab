# BUG-004 — Non-billing member can access restricted billing details

**Source ticket:** SUP-004  
**Severity:** Critical  
**Priority:** P0  
**Status:** Open  
**Escalation:** SECURITY + ENG-BUG

## Environment

- Web application
- Workspace member role without billing permission

## Preconditions

- Workspace contains billing information.
- Test user has a standard member role.
- A valid billing-page URL is known from an authorized session.

## Steps to reproduce

1. Sign in as a standard non-billing workspace member.
2. Paste the known billing details URL directly into the browser.
3. Load the page.

## Expected result

The server denies access and returns an authorization error or redirects the user to an allowed page.

## Actual result

The billing page loads and exposes billing details even though the navigation UI hides the Billing section for this role.

## Frequency

5/5 attempts with the tested role.

## Customer impact

Authorization failure can expose sensitive account and billing information to users who should not have access.

## Immediate containment

- Escalate as a security-sensitive P0.
- Review server-side permission checks for billing routes and APIs.
- Avoid relying on hidden UI navigation as an access-control mechanism.

## Retest criteria

- Standard members receive an authorization denial for direct billing URLs and underlying APIs.
- Authorized billing/admin roles retain access.
- Test role changes and stale sessions to confirm permissions are enforced server-side.
