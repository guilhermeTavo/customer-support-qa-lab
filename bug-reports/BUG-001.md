# BUG-001 — Password reset loop blocks account access

**Source ticket:** SUP-001  
**Severity:** High  
**Priority:** P1  
**Status:** Open  
**Escalation:** ENG-BUG

## Environment

- Web application
- Chrome 152 / Windows 11
- Also reproduced in Firefox 143

## Preconditions

- Existing active user account
- User requests password reset from the login screen
- Reset link is still valid

## Steps to reproduce

1. Open the password reset email.
2. Follow the reset link.
3. Enter and confirm a valid new password.
4. Submit the form.
5. Observe the next navigation step.

## Expected result

The password is updated and the user is redirected to the authenticated dashboard or login flow with a clear success state.

## Actual result

The password is updated, but the browser is redirected back to `/reset-password`, creating a loop. Repeating the flow does not restore normal access.

## Frequency

5/5 attempts in the tested account state.

## Customer impact

Affected users cannot reliably regain account access after using a core recovery workflow.

## Workaround

Support can manually invalidate the reset state and ask the user to sign in from a fresh session, but this is not a practical self-service workaround.

## Investigation notes

The authentication request succeeds. The failure appears after the password update during post-reset routing/state cleanup. Engineering should inspect reset-token/session invalidation and redirect logic.

## Retest criteria

- Reset password successfully.
- Confirm the user exits the recovery route.
- Confirm login with the new password.
- Confirm an expired/used reset link cannot be reused.
